## 1. このシステムでできること

「大阪府の製造業を50社」のように条件を指定すると、企業を自動で見つけて調べ、営業リストにします。

```
① 探す      複数の情報源（GビズINFO・Google Places・Web検索・EDINET）から企業候補を集める
② まとめる  同じ企業の情報を1つに統合する（重複を排除）
③ 確かめる  本当にその企業かを確認する（法人番号・公式サイト・所在地・電話）
④ 登録する  確認できた企業だけを営業リストに登録する
⑤ 調べる    公式サイトを巡回して、採用ページ・問い合わせ先・SNS・営業お断り表記を集める
⑥ 分析する  AI（Claude）が企業の状態を分析し、営業優先度をA〜Dでランク付けする
```

**大事な考え方**

- 検索結果に出てきた会社を、そのまま営業リストには入れません。必ず ③ の確認を通します。
- 確認しきれなかった候補は「確認待ちリスト」に入り、**人が承認するまで登録されません**。
- AI が推測した内容と、Web上で実際に確認できた事実は、画面上でも分けて表示します。
- メールアドレスを推測して作ることはしません（サイトに公開されているものだけを使います）。

## 2. ログインとアカウント

### ログイン

1. 管理者から共有された URL（例: `https://anyware-salesauto.vercel.app`）を開きます
2. メールアドレスとパスワードを入力します

ログアウトは左サイドバー下部の「ログアウト」から行います。

### 利用者の追加

Neon Console の画面からはパスワードを設定できないため、**利用者の作成はコマンドで行います**（管理者作業）。

```bash
npm run auth:create-user -- --email 名前@any-ware.jp --password '任意のパスワード'
```

利用者の削除は Neon Console の **Auth → Users** から行えます。

## 4. 企業を探す

左サイドバーの **「企業を探す」** を開きます。

### 4-1. 条件を入力する

| 項目 | 説明 |
| --- | --- |
| 都道府県 / 市区町村 | 市区町村は部分一致（例: 大阪市、東大阪市）。未指定なら主要都市に自動で分割して探します |
| 業種 | 大分類（製造業・建設業・IT など） |
| 業種詳細 | 「すべて（自動展開）」のままで構いません。指定すると金属加工・精密加工などに絞って探します |
| 探索方法 | 「自動（推奨）」のままで構いません。下記参照 |
| キーワード | 社名や事業内容に含まれる語 |
| 企業規模 / 従業員数 | 従業員数の範囲 |
| 法人種別 | 株式会社・有限会社など |
| 探索件数 | 営業候補として登録したい企業数（1〜500） |
| 公式HPを確認できた企業のみ | オンのとき、公式サイトを確認できなかった候補は登録しません（既定オン） |
| 採用活動あり | オンのとき、採用の痕跡が無い企業はクロールを省きます |

**探索方法**

| 選択肢 | 使う情報源 | 使いどころ |
| --- | --- | --- |
| 自動（推奨） | 利用できるものすべて | 通常はこれ。複数で突き合わせるため精度が最も高い |
| GビズINFO のみ | 法人番号つきの公的データ | 正確さを最優先したいとき |
| Google Places のみ | 地図データ | 地域密着の小さな会社を探したいとき |
| Web検索のみ | 検索エンジン | 他で見つからない会社を拾いたいとき（確認待ちが増えます） |

フォームの下に **「利用できる情報源」** が表示されます。APIキーが未設定の情報源はここに理由が出ます。
未設定でもエラーにはならず、使えるものだけで探索します。

### 4-2. 進捗を見る

「探索を開始」を押すと進捗画面に移動します。

| 数字 | 意味 |
| --- | --- |
| 新規候補 | 今回はじめて見つけた候補の数 |
| 確認済 | 本人確認を通過した候補（この後 企業登録されます） |
| 要確認 | 判断がつかなかった候補（**確認待ちリスト**へ） |
| 対象外 | 条件に合わない、または確認できなかった候補（登録しません） |
| 重複（別集計） | すでに登録済みだった企業。**新規候補には含みません** |
| 登録 | 実際に営業リストへ登録された企業数 |

**数字の見方**: `新規候補 = 確認済 + 要確認 + 対象外` です。
「重複」はこれとは別の集計なので、足し合わせないでください。
`新規候補 + 重複 = 見つけた候補の総数` になります。

**情報源ごとの内訳** の表で、どの情報源が何件見つけたか・失敗したかが分かります。
キーが未設定の情報源は「未使用」と理由が表示されます。

処理は次の順に進みます。画面を開いている間は自動的に進みます。

```
候補を発見中 → 本人確認中 → 営業候補へ登録中 → 完了
```

**画面を閉じても大丈夫です**（サーバー側で続きが処理されます）。ただし Vercel の無料プランでは自動処理が1日1回のため、
急ぐときは画面を開いたままにするか、ジョブ画面の「今すぐ処理を実行」を押してください。

### 4-3. 状態の意味

| 状態 | 意味 |
| --- | --- |
| 待機中 / 探索中 | 処理中です |
| 完了 | 目標件数まで探索できました |
| 一部完了 | 上限（時間・API回数・候補数）に達したため途中で終了しました。結果は保存されています |
| 失敗 | 使える情報源が無い、などの理由で開始できませんでした |
| 中止 | 「停止」を押して止めました |

## 5. 確認待ちリスト

左サイドバーの **「確認待ち」**（件数バッジ付き）を開きます。

自動判定で企業を断定できなかった候補の一覧です。**ここにある企業はまだ営業リストに入っていません。**

各カードには次が表示されます。

- 会社名・所在地・電話・法人番号
- どの情報源で見つかったか
- **本人確認スコア**（0〜100）と、その内訳（✓ 一致 / × 不一致）
- 公式サイトの候補 URL

### 操作

| ボタン | 動作 |
| --- | --- |
| **承認して企業に登録** | 営業リストへ登録し、公式サイトのクロールとAI分析を開始します |
| **対象外にする** | 却下します（登録しません） |
| **修正して再確認** | 公式サイトの URL を直して、自動確認をやり直します |

**確認のコツ**: 「公式サイトに会社名」が × になっている候補は、URL が別の会社のものである可能性があります。
リンクを開いて確認し、違っていれば正しい URL に直して「修正して再確認」を押してください。

## 6. 企業一覧

登録済みの企業を絞り込み・並べ替えできます。

**主なフィルタ**: 都道府県 / 業種 / 従業員数 / 営業ランク（A〜D）/ 採用課題あり / SNSなし / Web品質が低い / **営業可のみ（拒否・未確認を除外）** / 公式サイト要確認 / 未分析

「営業可のみ」は連絡可否が **「可」の企業だけ** を表示します。
「不明（未確認）」の企業は、営業してよいか確認できていないため除外されます。

**CSV エクスポート**: 絞り込んだ結果をそのまま CSV で出力できます。列には企業情報・連絡先・SNS・各スコア・営業ランク・AI分析の概要が含まれます。

## 7. 企業詳細

企業名をクリックすると詳細画面が開きます。

| セクション | 内容 |
| --- | --- |
| 基本情報 | 法人番号・所在地・業種・従業員数・設立・代表者 |
| 公式Webサイト・問い合わせ | 公式サイト URL とその信頼度、問い合わせページ・フォーム・メール・電話 |
| SNS | Instagram / Facebook / X / YouTube / LinkedIn / TikTok |
| 採用状況 | 採用ページの有無、新卒・中途の募集状況 |
| AI分析 | 企業概要・事業概要・各スコア・営業ランク・課題・強み・提案トピック・**確認できた事実**・**AIの推測**・分析理由・根拠（Evidence） |
| クロールページ | 実際に取得したページの一覧 |
| 処理履歴 | クロール・AI分析の実行履歴 |
| **情報源** | どの情報源が何を観測したか（会社名・所在地・電話・サイト・法人番号）。値の出どころを確認できます |

### スコアの意味

| スコア | 高いほど |
| --- | --- |
| 採用ページ品質 | 採用ページが充実している |
| 採用課題 | 採用面の課題が大きい（＝提案余地がある） |
| Web品質 | サイトの作りが良い |
| SNS活動 | SNS を活発に運用している |
| デジタルマーケティング | Web集客に取り組んでいる |
| DX機会 | デジタル化の提案余地が大きい |
| 成長ポテンシャル | 成長が見込める |
| **営業優先度** | 上記を合成した総合点。A（高）〜D（低）のランクになります |

### 「確認できた事実」と「AIの推測」

- **確認できた事実**: Web上に実際に書かれていた内容です。根拠 URL が併記されます
- **AIの推測**: 事実から AI が推し量った内容です。**そのまま事実として使わないでください**

従業員数が「公式サイト記載としてAIが読み取り」と注記されている場合、それは公的な登録データではありません。

### 公式サイトが「要確認」のとき

「公式Webサイト」セクションで候補 URL を選ぶか、正しい URL を入力して保存できます。保存すると再クロール・再分析されます。

### 連絡可否（営業拒否）

| 表示 | 意味 |
| --- | --- |
| 可 | 営業お断りの表記が見つからず、問い合わせ系ページも確認できた |
| 不明 | 確認できていない（問い合わせページを取得できていない等）。**「可」と断定はしません** |
| 営業不可 | 営業お断りの表記が見つかった。自動送信からは必ず除外されます |

手動で上書きもできます（誤検出の修正など）。

### 再解析 / AI分析のみ

- **再解析**: 公式サイトをもう一度クロールしてから AI 分析します
- **AI分析のみ**: 取得済みのページを使って AI 分析だけをやり直します（クロールしないので早い）

## 9. ジョブ画面・ログ画面

### ジョブ画面

クロール・AI分析の状況を確認できます。

- **今すぐ処理を実行**: 待機中の処理をその場で進めます
- **失敗した件数を再実行**: 失敗したものだけをやり直します（成功済みには影響しません）

### ログ画面

探索・登録・クロール・分析・エラーのログと、Claude API の使用量（トークン数）を確認できます。
うまくいかないときは、まずここでエラー内容を確認してください。

## 10. 営業拒否企業の扱い

「営業お断り」「営業目的のお問い合わせはご遠慮ください」等の表記を、ルールと AI の両方で検出します。

- 検出された企業は **連絡可否が「営業不可」** になります
- 同時に **抑止リスト（suppression_list）** に自動登録されます
- 一度「営業不可」になった企業は、再分析しても自動では「可」に戻りません
- 将来のメール自動送信・フォーム自動送信では、このリストを必ず除外します

**確認できていない場合は「不明」のままにします。** 根拠なく「営業可」とは判定しません。

## 11. 運用ルールと注意点

### クロールについて

- `robots.txt` を尊重し、禁止されたページは取得しません
- 1社あたり最大20ページ、リクエスト間隔は1秒以上（サイトに負荷をかけません）
- ログイン必須のサイト、CAPTCHA で保護されたサイト、利用規約でスクレイピングが禁止されているサイトは取得しません

### 個人情報・メールアドレス

- **メールアドレスを推測して作ることはしません。** サイトに公開されているものだけを使います
- 会社の代表アドレス（info@ 等）を優先し、制作会社など他社ドメインのアドレスは採用しません
- 個人名の記載は営業目的以外に利用しないでください

### API コスト

- 実データモード（`DATA_MODE=live`）では、Claude・GビズINFO・Google Places・Brave Search の API を消費します
- 1回の探索で使える API 回数・時間には上限が設定されています。上限に達すると「一部完了」で安全に停止します
- 動作確認だけしたい場合はモックモード（`DATA_MODE=mock`）を使ってください。API を一切消費しません

### 探索件数の目安

まずは 20 社程度で試し、結果の精度（確認済みと確認待ちの比率、公式サイトの正しさ）を確認してから
50社・100社と増やしてください。

## 12. 管理者向け設定

設定は Vercel の **Settings → Environment Variables** で行います（値はコードに書きません）。

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | Neon の接続文字列 |
| `NEON_AUTH_BASE_URL` / `NEON_AUTH_COOKIE_SECRET` | ログイン機能 |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | AI分析 |
| `GBIZ_API_KEY` | GビズINFO（法人番号の正） |
| `GOOGLE_MAPS_API_KEY` | Google Places（任意） |
| `BRAVE_SEARCH_API_KEY` | Web検索（任意） |
| `EDINET_API_KEY` | 上場企業の裏付け（任意） |
| `DISCOVERY_MODE` | 既定の探索方法（`hybrid` 推奨） |
| `DISCOVERY_MAX_*` | 1回の探索の上限（API 料金事故の防止） |
| `CRAWL_MAX_PAGES` | 1社あたりのクロールページ数（既定 20） |
| `CRON_SECRET` / `JOB_SECRET` | 自動処理の認証 |

**これらの値に `NEXT_PUBLIC_` を付けないでください。** ブラウザに漏れます。

### 本人確認の厳しさを変える

`src/lib/config/discovery.ts` の `weights`（配点）と `thresholds`（しきい値）を変更します。

- 確認待ちが多すぎる → `thresholds.verified` を下げる（例: 80 → 70）
- 誤登録が心配 → `thresholds.verified` を上げる

### 設定の確認

```bash
npm run preflight
```

APIキーの有効性・モデル名・利用できる情報源・本人確認のしきい値・予算が一覧表示されます。
**秘密情報そのものは表示されません。**

## 13. トラブルシューティング FAQ

| 症状 | 対処 |
| --- | --- |
| ログインできない | 利用者が未作成の可能性。`npm run auth:create-user` で作成してください |
| ログイン画面に赤字で設定不足が出る | `NEON_AUTH_BASE_URL` / `NEON_AUTH_COOKIE_SECRET` が未設定です |
| 「Invalid origin」と出る | Neon Console → Auth → Configuration に本番URLと `http://localhost:3000` を追加してください |
| 探索が進まない | ジョブ画面の「今すぐ処理を実行」を押すか、進捗画面を開いたままにしてください |
| 「利用できる情報源がありません」 | APIキーが1つも設定されていません。`GBIZ_API_KEY` から設定してください |
| 確認待ちばかり増える | 情報源が1つしか無い可能性があります。Google Places / Brave Search を追加すると突き合わせが効きます |
| 公式サイトが違う会社になっている | 確認待ちリストまたは企業詳細で URL を修正してください |
| 「一部完了」で終わる | 上限に達しました。もう一度同じ条件で探索すると続きから増やせます（重複は自動で除外されます） |
| 企業が登録されない | 確認待ちリストを確認してください。承認するまで登録されません |

## 14. 用語集

| 用語 | 意味 |
| --- | --- |
| 探索（Discovery） | 複数の情報源から企業候補を探す処理 |
| 候補 | まだ企業として登録していない、確認前のデータ |
| 本人確認スコア | その候補が本当にその企業かの確からしさ（0〜100） |
| 確認済（verified） | 本人確認を通過し、営業リストに登録された企業 |
| 要確認（needs_review） | 人の判断が必要な候補。承認するまで登録されません |
| 情報源（Source） | GビズINFO・Google Places・Web検索・EDINET・公式サイト確認 |
| 法人番号 | 国が付与する13桁の番号。最も確実な企業の識別子 |
| クロール | 公式サイトのページを巡回して本文を取得すること |
| Evidence（根拠） | AI の判断のもとになった、実際のページの URL と引用 |
| 営業優先度ランク | A（最優先）〜D（優先度低） |
| 抑止リスト | 自動送信から必ず除外する企業・メール・ドメインのリスト |
